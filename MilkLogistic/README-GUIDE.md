# MilkLogistic — подробный гайд

Практическое руководство: что нажимать, что происходит внутри и как проверить локально.
Скриншоты не нужны — все экраны описаны по элементам.

---

## 1. Что это

Сервис планирования доставки «Молочного Мира» по Гродно:

- заявки и парк берутся из JSON (штатный файл или выгрузка 1С);
- расстояния и время — реальные дорожные (OSRM, локальная карта Гродно);
- план учитывает грузоподъёмность, минимальную загрузку 90 %, узкие улицы, окна доставки,
  обед и 8-часовую смену;
- маршруты выдаются водителям по персональным ссылкам;
- водитель отмечает доставку, логист видит прогресс;
- остаток можно закрыть дополнительным заездом.

## 2. Запуск и ссылки

```bat
cd MilkLogistic
start.bat        :: поднять стек (Docker Desktop должен быть запущен)
stop.bat         :: остановить
```

| Что открыть | Адрес |
|---|---|
| Планирование (главная) | http://localhost:8080 |
| Кабинет логиста | http://localhost:8080/dispatch |
| Маршрут водителя | http://localhost:8080/driver/&lt;token&gt; (ссылка выдаётся в кабинете) |
| Пример выгрузки 1С | http://localhost:8080/examples/1c-example-day.json |
| Маленький пример 1С | http://localhost:8080/examples/1c-example-small.json |
| Swagger (все API) | http://localhost:8000/docs |
| Страница проверки + история прогонов | http://localhost:8000/ |
| HTML-отчёт по прогону | http://localhost:8000/api/runs/&lt;run_id&gt;/report |
| GeoJSON маршрутов | http://localhost:8000/api/runs/&lt;run_id&gt;/geojson |
| Сервис маршрутизации | http://localhost:8100/api/health |

Проверка живости: `http://localhost:8000/api/health` — должно быть `"status":"ok"` и `matrix.ready: true`.

### 2.1 Десктоп (Electron)

```bash
cd MilkLogistic
npm install
npm run electron:start   # окно с приложением (бэкенд уже должен работать)
npm run electron:build   # release/MilkLogistic Setup 1.0.0.exe и portable
```

Electron поднимает локальный сервер для `dist/` и открывает окно. Расчёты выполняет бэкенд
по адресу `http://localhost:8080`. Если API на другом адресе — задайте `MILK_API_BASE`
или `milk-config.json` рядом с exe:

```json
{ "apiBase": "http://localhost:8000" }
```

### 2.2 Онлайн-версия (GitHub Pages)

https://artemiysd.github.io/MilkLogistic/ — собирается workflow при пуше в `develop`/`main`
и публикуется в ветку `gh-pages`. Для работы расчётов нужен публичный API:
задайте `API_BASE_URL` в Settings → Secrets and variables → Actions → Variables.
SPA-маршруты (`/dispatch`, `/driver/...`) работают через `404.html`.

## 3. Роли

**Логист** — главная страница + кабинет: строит план, проверяет 90 %, отправляет маршруты,
решает, что делать с недогрузом, следит за прогрессом.

**Водитель** — открывает персональную ссылку на телефоне. Пароля нет: ссылка = доступ.
Отмечает «Доставлено» / «Не доставлено», сообщает о проблемах.

---

## 4. Главная страница

Сверху шаги **1 Данные → 2 План → 3 Водители** и ссылки «Скачать пример 1С», «Кабинет логиста».

### 4.1 Блок «Данные рейса»

| Элемент | Значение |
|---|---|
| Название набора | Активные данные: «Штатные данные (logistics_data.json)» или имя выгрузки |
| Адресов доставки | Число заявок (214) |
| Машин в парке | Физические машины (16) |
| Общий вес заявок | Суммарный груз (63 630 кг) |

### 4.2 Кнопки

| Кнопка | Что делает |
|---|---|
| **Построить маршруты** | `POST /api/optimize`: полный расчёт по активным данным. 1–3 секунды |
| **Загрузить 1С / JSON** | Импорт файла. Если плана нет — файл становится активным набором. Если план есть — файл запоминается для доп. заезда, экран не сбрасывается |
| **Скачать пример 1С (JSON)** | Скачивает `1c-example-day.json` |
| **Доп. заезд по остатку** | Появляется, если есть неразвезённые адреса. Если загружен новый файл — «Доп. заезд (+N из 1С)» |

### 4.3 Карта

- «Все точки» — все адреса и склад, есть поиск.
- «Маршруты» — линии рейсов и кнопки вида `truck_4t_1-2 · 98 %`.
  - обычная кнопка — загрузка ≥ 90 %;
  - **оранжевая** — ниже 90 %;
  - клик показывает только выбранный рейс.

### 4.4 Блок «Результат»

| Карточка | Смысл |
|---|---|
| Доставлено | процент и кг от общего груза |
| Не развезено | адреса и кг, которые не влезли в смены |
| Пробег | оптимизированный, «было» (порядок накладной) и экономия |
| Машин в рейсах | сколько машин реально задействовано |

### 4.5 «Проверка плана логистом» — правило 90 %

Рейс считается недогруженным, если `вес < грузоподъёмность × 0,9`.
Такие машины **не отправляются автоматически** — решение принимает логист.

| Кнопка | Что происходит |
|---|---|
| **Отправить N рейсов ≥ 90 %** | Создаёт задания только для нормально загруженных рейсов. Недогруженные остаются на главной |
| **Отправить все M** | Отправляет и недогруженные (осознанное решение) |
| **Пересчитать без недогруза** | Новый план, в котором рейсы < 90 % сняты. Их адреса уходят в «не развезено» — их можно закрыть доп. заездом |
| ничего не нажимать | «Не отправлять»: маршруты просто не выдаются |

## 5. Как считается план

1. **Валидация** JSON: обязательные разделы, ID, вес > 0, окна, ограничения.
2. **Адреса**: 214 заявок → 192 остановки (заявки одного адреса суммируются).
3. **Матрица OSRM** 215×215: метры и секунды между адресами. Для выгрузки 1С строится своя.
4. **Распределение**:
   - сначала «развезти всё с загрузкой 90–100 %» — перебор сочетаний машин + упаковка;
   - если невозможно — «развезти максимум» (жадная упаковка, обмены заявок, вариант «по 90–100 %»);
   - **перебалансировка**: заявки из недогруженного рейса переезжают в другие машины.
5. **Порядок объезда**: ближайший сосед с учётом окон → or-opt (перестановка) → 2-opt (разворот участка).
6. **Расписание**: погрузка 30 мин, перегоны по матрице, выгрузка 30 мин/адрес, обед 13–14
   (в рабочее время не входит), лимит 8 ч, возврат ≤ 17:00.
7. **Водители**: длинные рейсы первыми, водитель может взять вторую машину, если успевает.
8. **Итоги**: кг, адреса, пробег, экономия к порядку накладной.

Текущий результат на штатных данных: **16 рейсов, 631,5 км против 658,3 км (−4,1 %),
59 940 из 63 630 кг, 31 адрес / 3 690 кг не влезает**. Три рейса ниже 90 % — на решение логиста.

## 6. Кабинет логиста

### 6.1 Шапка

Показывает текущую смену: набор данных, дату, число маршрутов.

| Кнопка | Действие |
|---|---|
| **Начать смену заново** | Отменяет все маршруты и удаляет водителей. Полный сброс |
| **К планированию** | На главную |

### 6.2 Счётчики

Водителей в смене, маршрутов выдано, точек доставлено, точек всего.
Показывается **только последняя выдача** — старые смены не смешиваются.

### 6.3 «Как водитель смотрит маршрут»

1. «Открыть маршрут» у водителя.
2. Скопировать ссылку и отправить водителю (работает на телефоне без пароля).
3. Водитель отмечает доставку — точка исчезает с карты, здесь растёт прогресс.

Кнопки:

| Кнопка | Действие |
|---|---|
| **Посмотреть как водитель** | Открывает маршрут первого водителя в новой вкладке |
| **Скопировать первую ссылку** | Кладёт ссылку в буфер обмена |
| Нужен другой маршрут? | Ссылка на главную, чтобы построить план |

### 6.4 Водители смены

| Кнопка | Действие |
|---|---|
| **Добавить** | Добавить водителя: имя, телефон, машина (необязательно) |
| **Создать по парку** | По водителю на каждую машину активного набора |
| **Убрать свободных** | Удаляет водителей без маршрутов |
| «открыть» | Персональная страница водителя |
| «копировать» | Ссылка в буфер обмена |
| «удалить» | Удалить водителя |

### 6.5 Маршруты смены

Карточка: водитель, машина, точек, км, дата выдачи, статус, прогресс.

| Кнопка | Действие |
|---|---|
| **Открыть маршрут** | Страница водителя |
| **Пересчитать остаток** | Новый порядок только невыполненных точек с текущего времени, та же машина. Доставленные/отказные сохраняются |
| **Отменить** | Маршрут отменяется, ссылка перестаёт работать |

## 7. Страница водителя

Открывается по ссылке `/driver/<token>`.

- шапка: имя, телефон, статус;
- показатели: машина, **остаток пробега**, время возврата, сколько осталось;
- прогресс-бар: доставлено из всего, проблемные;
- карта: **только оставшиеся точки и линия до них**;
- список точек: адрес, «прибыть / выгрузить», вес, число заявок.

| Кнопка | Действие |
|---|---|
| **Доставлено** | Точка закрывается, исчезает с карты; маршрут перерисовывается через оставшиеся точки; «пробег» уменьшается |
| **Не доставлено** → причина → **Подтвердить** | Причины: клиент закрыт, отказ, не успел, нет доступа, другое |
| **Сообщить логисту о проблеме** | Событие в журнал, маршрут помечается `problem` |

Ниже — закрытые точки и журнал событий. Страница сама обновляется каждые 15 секунд.

После каждого действия линия маршрута строится заново: от последней закрытой точки
(или склада) через оставшиеся и обратно на склад — поэтому путь до закрытой точки исчезает.

## 8. Пересчёты — чем отличаются

| Действие | Где | Что меняется | API |
|---|---|---|---|
| Построить маршруты | Главная | Полный новый план по активным данным | `POST /api/optimize` |
| Пересчитать без недогруза | Главная | Тот же план, но рейсы < 90 % снимаются; их адреса → «не развезено» | `POST /api/runs/{id}/rebalance` |
| Доп. заезд | Главная | Остаток первой волны (+ новая 1С) на машины, вернувшиеся до 16:00, старт 13:00 | `POST /api/runs/{id}/extra` |
| Пересчитать остаток | Кабинет | Для одного водителя: оставшиеся точки с текущего времени | `POST /api/assignments/{id}/replan` |
| Начать смену заново | Кабинет | Отмена всех маршрутов + удаление водителей | `POST /api/dispatch/reset` |

Пример: «без недогруза» даёт 13 рейсов и 67 адресов в остатке; доп. заезд закрывает
часть остатка (в тесте 31 адрес → 5).

## 9. Импорт 1С

Минимальный JSON:

```json
{
  "meta": { "date": "2026-11-16", "document_number": "1C-000123", "source": "1c" },
  "depot": { "id": "depot_1", "address": "Гродно, Гаспадарчая 28",
             "coords": { "lat": 53.708928, "lon": 23.828288 } },
  "vehicles": [{ "id": "truck_5t", "name": "5 т", "capacity": 5000, "count": 1 }],
  "delivery_points": [
    { "id": "p1", "name": "Магазин", "address": "Советская 10", "street": "Советская",
      "demand": 350, "coords": { "lat": 53.67, "lon": 23.82 } }
  ],
  "constraints": { "min_load_ratio": 0.9, "max_workday_hours": 8, "unload_time_minutes": 30 }
}
```

Что происходит:

1. Проверка контракта (ошибка → 422 с понятным текстом).
2. Набор сохраняется в `data/imports/`.
3. По координатам строится матрица через сервис маршрутизации.
4. Набор становится активным: главная и `/api/optimize` работают с ним.
5. Если координат нет — импорт проходит, но карта не строится, расстояния — запасная
   оценка; в интерфейсе предупреждение.

Команды:

```bash
curl -X POST "http://localhost:8000/api/import/file?activate=true" -F "files=@vypiska.json"
curl -X POST "http://localhost:8000/api/import" -H "Content-Type: application/json" --data-binary @vypiska.json
curl http://localhost:8000/api/datasets
curl -X POST http://localhost:8000/api/datasets/active -H "Content-Type: application/json" -d '{"dataset_id": null}'
```

## 10. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | состояние, матрица, активный набор, водители |
| GET | `/api/data` | склад, машины, точки, ограничения, название набора |

| GET | `/api/runs/{id}/report` | HTML-отчёт с картой |
| POST | `/api/runs/{id}/dispatch` | выдать рейсы (`allow_underloaded`, `exclude_routes`) |
| POST | `/api/runs/{id}/rebalance` | пересчёт без недогруза |
| POST | `/api/runs/{id}/extra` | доп. заезд (`dataset_id`, `start_time`) |
| GET | `/api/dispatch` | сводка текущей смены |
| POST | `/api/dispatch/reset` | сброс смены |
| GET/POST/PATCH/DELETE | `/api/drivers` | база водителей |

## 13. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Пустая карта, «Нет координат» | В выгрузке нет `coords` у склада/точек. Добавьте координаты |
| Много водителей | База накапливается между сменами: «Начать смену заново» или «Убрать свободных» |
| «Нет рейсов ≥ 90 %» | Все рейсы недогружены: «Отправить все» или пересчёт/догрузка |
| «Не хватило водителей» | Рейсов больше, чем водителей: добавьте вручную |
| «Нет машин, освободившихся до 16:00» | Все машины заняты до вечера — доп. заезд невозможен |
| Матрица не собрана | Проверьте `http://localhost:8100/api/health` и координаты |
| Водитель не видит маршрут | Ссылка устарела (маршрут отменён/завершён) — выдайте заново |
